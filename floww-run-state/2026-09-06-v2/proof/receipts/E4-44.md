## What the code does

### discord_ops.py

The core of the G3 paper loop is `execute_approve()`:

1. Fetches recent alerts via `fetch_recent_alerts(engine, limit=50)`.
2. If `rows is None` (feed failed, not empty), returns `status=error` and
   `reason` containing `unavailable`, plus the `alert` key — never
   "alert not found". This is the feed-unavailable contract.
3. Finds the alert by key. If missing, returns `status=error` with the key.
4. Verifies bias is BULLISH or BEARISH. If not, returns `status=error` with
   "no directional bias".
5. Derives side from bias: BULLISH→buy, BEARISH→sell.
6. Looks up the underlying symbol from the alert.
7. Defaults qty to 1 if not supplied, requires qty > 0.
8. Checks the duplicate guard `_approve_already_journaled(alert_key)`. If the
   same alert key already has a discord-approve seed in the last 30 days of
   journal trades, returns `status=duplicate` with the key.
9. Submits through the real `OrderRouter` with `allow_market=True`. The router
   defaults `ALLOW_MARKET_ORDERS=False` and rejects market orders unless
   opted in per-call. This is the safety gate.
10. If the router returns `status=submitted`, reconciles the fill via
    `_reconcile_fill()` and journals the seed via `_journal_approve_fill()`.
11. Returns `status=submitted`, the order, the alert key, and the reconciliation.
12. If the router returns anything else, returns that status and the order.
13. Catches `TypeError` for back-compat when the router stub lacks
    `allow_market`, and all other exceptions, returning `status=error` with the
    reason. Never raises into the trade path.

Reconciliation `_reconcile_fill()`:
- Reads the broker dict from the order response.
- Extracts the venue order id.
- Calls `router.fetch_venue_order(venue_id)` if available.
- Returns `venue_status` from the fetched order, or `unknown` if the broker
  lacks the read path or the fetch fails.
- Never raises; returns `unknown` with a reason on failure.

Journal `_journal_approve_fill()`:
- Records the trade as `type=equity`, NOT an option. This is correct because
  `place_stock_order` buys/sells the underlying equity.
- Stores `strike` as the underlying reference price (or 0.0), labeled in the
  notes as "equity leg, not a strike".
- Stores full timestamp `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%S")` so
  same-day re-trades don't PK-collide and silently vanish.
- Notes include: the alert rule/tier/key, the broker id, the broker status
  (labeled "submission, not a confirmed fill; reconcile via get_order"), the
  reconciliation bits if available, the reference price, and the alert why.
- Fail-open: never raises into the trade path. Only logs a warning.

Duplicate guard `_approve_already_journaled()`:
- Reads the journal for trades with `source=discord-approve` in the last 30
  days and checks if the alert key appears in the notes.
- Fail-open: any read error means "not seen", the trade proceeds. This is
  correct for a dedup guard — false negatives are safe (a duplicate might
  slip through), false positives are dangerous (legitimate trades blocked).

### order_router.py

`OrderRouter`:
- Hardcodes `VENUE = "alpaca-paper"`.
- Defaults `ALLOW_MARKET_ORDERS = False`.
- `submit_order(intent, db=None, allow_market=False)`:
  - Builds a client_order_id from sha256(signal_id:timestamp_us)[:16].
  - Checks the cache first; if the client_order_id is already cached, returns
    the cached response with an info log. This is the in-memory dedup.
  - Calls `_build_order_payload()` which rejects MARKET orders unless
    ALLOW_MARKET_ORDERS or allow_market is True.
  - On market rejection, returns `status=rejected` with the reason.
  - On submission, caches the response for dedup, updates the position tracker,
    persists positions if db is provided, and returns the result.
  - On any exception, returns `status=error` with a named reason.
- `fetch_venue_order(venue_order_id)`:
  - Returns None if no venue_order_id.
  - Calls `broker.get_order(venue_order_id)` if the broker has it.
  - Returns the dict or None. Never raises into the trade path.
- `get_positions_from_alpaca()` and the back-compat alias
  `get_positions_from_schwab()` both call the same Alpaca read path.

PositionTracker:
- In-memory positions dict plus Mongo persistence every 10 seconds.
- `persist(db)` upsertes positions with updated_at.
- `hydrate(db)` loads positions from Mongo on startup.

### alpaca_client.py

`AlpacaClient`:
- Hardcodes `ALPACA_BASE_URL = "https://paper-api.alpaca.markets"` and
  `ALPACA_DATA_URL = "https://data.alpaca.markets"`.
- Keys loaded from env at call time, not import time.
- `enabled` property checks both keys are set.
- `_get/_post/_delete` return None on failure; `last_failure()` returns the
  honest http_status and detail.
- `classify_alpaca_http(status, body)` maps HTTP outcomes to honest reasons:
  - 200/201 → ok
  - 207 → ok + partial
  - 401 → unauthorized, check keys
  - 403 → venue rejected, likely no options approval
  - 404 → not found, bad order/contract id
  - 422 → rejected parameters, body echoed
  - 429 → rate-limited, back off
  - 5xx → venue error, retryable
  - None → no venue response, timeout/unreachable
- `get_order(order_id)` — fetch one paper order by venue ID (used for
  reconciliation reads).
- `verify_bracket_legs(order_id)` — G3.4 follow-through:
  - Fetches the order.
  - If not found, returns verified=False with the order_id and the last
    failure detail.
  - Extracts legs, filters to dicts.
  - If no legs, returns verified=False with "no legs on bracket order" reason.
  - If any leg is not in LIVE_LEG_STATUSES, returns verified=False with the dead
    leg ids.
  - Otherwise returns verified=True with the legs and order status.
- `place_stock_order(symbol, qty, side, order_type, limit_price)` — places a
  stock order on paper, returns the order dict or None.
- `close_position(symbol)` — closes a position, returns the close message or
  None.
- `get_positions()` — lists open paper positions.
- `get_account()` — paper account info.
- `get_orders(status, limit)` — orders by status.
- `get_clock()` — market clock.
- `cancel_order(order_id)` — cancels an open paper order.
- `get_bars(ticker, timeframe, limit)` — stock bars from Alpaca data.
- `normalize_option_symbol(symbol)` — normalizes OCC symbols for Alpaca,
  returns "" if not a valid OCC contract.
- `place_option_order(symbol, qty, side, order_type, limit_price, time_in_force)` —
  places an option order on paper, requires options approval (403 otherwise,
  surfaced honestly).
- `place_bracket_order(symbol, qty, side, take_profit_price, stop_loss_price,
  time_in_force)` — bracket order on paper: market entry + TP limit + stop legs.
  Returns the order with legs or None.

The paper venue constant is asserted by the test
`test_paper_venue_hardcoded`.
