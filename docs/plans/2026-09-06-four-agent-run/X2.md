# X2 — Phase 9 compose and consumer acceptance (Agent 3 frontend)

## Why

RECOVERY-QUEUE.md agent-3 backlog item 3. Phase 9 compose (`FlowseekerProBlademap`)
is the primary Flowseeker Pro consumer surface. It mounts multiple sub-components (feed,
chart, tracker, filters, drawer, modal, quote/dealer panels) and the integration between
them must be verified as a mounted consumer — not as isolated unit tests that don't
exercise the real mounting, prop-passing, and state-flow behavior.

This task is the consumer acceptance verification for the Phase 9 compose surface. It
builds on QUEUE.md's X2 contract and the existing `FlowseekerProBlademap.test.jsx` suite,
extending it to cover the real mounted-behavior scenarios that matter: filters, drawer,
tracker, modal, quote/dealer, and the empty/stale/error states.

## Admission criteria (read before admitting)

- [ ] Agent 1 has confirmed this is the next agent-3 frontend task.
- [ ] The `FLOWSEEKER-1A` receipt is reviewed — badge-wiring is done, this task is about
      the compose surface that hosts those badges, not re-wiring them.
- [ ] Boot artifact written to run-state before any work.
- [ ] Any App.js edits require a recorded standing waiver (App.js is frozen without one).

## Scope (what this task covers)

### Composed surface: `FlowseekerProBlademap`
- Verify each intended existing surface has a path to render, OR an explicit retired/gated
  receipt explaining why it doesn't.
- Exercise filters, drawer, tracker, modal, quote/dealer panels with recorded sanitized
  payloads — real components, not JSON/node assertions masquerading as UI tests.
- Inspect 360/768/1440px layouts for clipping, horizontal tape scrolling, keyboard access.
- No v2 redesign without B0 — this task verifies the CURRENT compose surface, not redesigns.

### What "mounted consumer acceptance" means here

A mounted consumer test renders the actual `FlowseekerProBlademap` component (or a
meaningful subtree) with real props and exercises it as a user would: toggle filters,
open/close drawer, interact with tracker, trigger modal, read quote/dealer panels. The
test verifies the rendered output matches expectations — not just that functions return
the right values in isolation.

### Existing test coverage to build on

- `FlowseekerProBlademap.test.jsx` — existing suite, extend targeted scenarios.
- Individual component tests (feed, chart, tracker, etc.) — read as reference, but this
  task's value is in the COMPOSE-level verification, not re-proving each leaf.

## Exclusions

- No backend changes — this is frontend-only.
- No new alpha, thresholds, or signal changes — verify the existing compose surface, don't
  change what it computes.
- No App.js edits unless Agent 1/Nav records a standing waiver.
- No Tidehunter/B0 redesign work — that's blocked on its real brief/mockups.
- No re-litigation of badge-wiring (FLOWSEEKER-1A) — badges are already wired; this task
  verifies they render correctly in the compose surface.

## Deliverable

A receipt file (X2-receipt.md) containing:

1. **Surface reconciliation**: for each intended Phase 9 compose surface, the verdict —
   renders correctly / renders with known gap / retired / gated. Each verdict cited to a
   test, a visual inspection, or an explicit reason.
2. **Mounted-behavior test results**: which scenarios were tested mounted, which passed,
   which failed, and why.
3. **Layout inspection**: 360/768/1440px findings — clipping, scrolling, keyboard access
   issues, if any.
4. **Gap list**: any surface that doesn't render as intended, with a one-line description
   of what's wrong and what a fix would need. Each gap is a separate admitted unit.
5. **Blocker list**: any surface that needs a product decision flagged for Nav/Agent-1.

## Test discipline

- Every new test must fail before the fix and pass after — no skipping, no xfailing
  passing tests.
- Full-suite green before commit (CRACO test --watchAll=false from frontend/).
- Build clean before commit.
- If a test can't be written for a scenario (e.g. it needs a browser), say so explicitly
  in the receipt — don't fake it with a node assertion.
