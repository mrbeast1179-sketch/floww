### Issue 5

```
FILE: backend/services/backtest/engine.py
LINE: 97–111 (BUY_CALL), 121–135 (BUY_PUT)
SEVERITY: CRITICAL
TYPE: NumericalInstability / LogicError
DESCRIPTION: Entry slippage is double-counted. `entry_price` is set to
  `close_price * (1.0 + cfg.slippage_pct)` (slippage baked into entry price), then
  `slippage_cost = close_price * cfg.slippage_pct * contracts` is added AGAIN as a
  separate fee subtracted from equity. At trade close, `gross_pnl` uses `position.entry_price`
  (already inflated) and `net_pnl` deducts `entry_slippage` (= slippage_cost) a second
  time. Every trade's net_pnl understates true profit by `close * slippage_pct * qty`,
  systematically corrupting all backtest Sharpe ratios and equity curves.
SUGGESTED FIX: Choose one approach. Either (a) set `entry_price = close_price` and charge
  slippage only via `slippage_cost`, or (b) embed slippage into `entry_price` and do NOT
  add `slippage_cost` separately. Option (a) is cleaner:

  entry_price = close_price
  slippage_cost = close_price * cfg.slippage_pct * cfg.contracts_per_trade
  cost = entry_price * cfg.contracts_per_trade + commission_cost + slippage_cost
  position.entry_price = entry_price  # net of slippage tracked separately
```

### Issue 7

```
FILE: backend/services/numba_greeks.py
LINE: ~287 (bs_vega_vec), backend/bs_greeks.py LINE: ~118 (bs_vega)
SEVERITY: HIGH
TYPE: NumericalInstability
DESCRIPTION: `bs_vega_vec` in `numba_greeks.py` divides its output by 100:
  `out[i] = S * exp(-q*T) * _norm_pdf(d1) * sqrt(T) / 100.0`.
  `bs_vega` in `bs_greeks.py` does NOT divide by 100:
  `result = S * math.exp(-q * T) * norm.pdf(d1) * math.sqrt(T)`.
  The two vega implementations disagree by a factor of 100. `vomma_vec` in
  `numba_greeks.py` inherits this scaled vega in its calculation, compounding
  the error. Any GEX/VEX dollar-exposure calculation that mixes the two
  modules will be off by 100×. No cross-module test exists to catch this.
SUGGESTED FIX: Decide the canonical convention (per-unit vol or per-1% vol). If
  dividing by 100 is intentional in numba_greeks (per-1% convention), add the same
  division to `bs_greeks.py::bs_vega` and document the convention. Add an integration
  test: for identical inputs, `bs_vega(S,K,T,sigma,q) ≈ bs_vega_vec([S],[K],[T],[sigma],[q])[0]`.
```

### Issue 8

```
FILE: backend/bs_greeks.py
LINE: 28 (bs_call_price), 44 (bs_put_price) vs 58 (bs_delta), 75 (bs_gamma), etc.
SEVERITY: HIGH
```

### Issue 9

```
FILE: backend/services/ml/realtime_features.py
LINE: ~89 (fetch_live_chain spot estimation)
SEVERITY: HIGH
TYPE: InferenceBug
DESCRIPTION: `fetch_live_chain()` estimates the underlying spot price as:
  `spot = strike + mid if mid > 0 else float(chain.calls["strike"].median())`
  where `mid` is the option mid-price. Adding an option's mid-price to its strike
  does not yield the underlying spot. For a $500 strike ATM call with $5 mid,
  this returns $505 instead of ~$500. Spot price is used downstream to compute
  `dist_to_flip`, GEX z-score normalization, and other features — all will be wrong.
SUGGESTED FIX: Estimate spot from underlying data, not option prices. Use
  yfinance `fast_info.last_price`, or compute ATM from the call/put price pair
  via put-call parity, or use the median of strikes weighted by OI near ATM.
```

```
FILE: backend/ml_training.py
LINE: 74–82 (train/test split)
SEVERITY: HIGH
TYPE: DataLeakage
DESCRIPTION: 80/20 chronological split uses no embargo period. The test set immediately
```

### Issue 17

```
FILE: backend/ml_advanced.py
LINE: 147–162 (train_with_walkforward_cv fold selection)
SEVERITY: HIGH
TYPE: LogicError / InferenceBug
DESCRIPTION: Walk-forward CV selects the "best" fold model by highest fold accuracy
  (`if acc > best_acc: best_model = ...`). Fold accuracy is an in-sample metric within
  that fold's test window; it rewards models that overfit to local regimes. The correct
  selection criterion for a production model is OOS Sharpe (or OOS accuracy averaged
  across all folds), not the best single-fold accuracy.
SUGGESTED FIX: Average metrics across all folds and select based on mean OOS Sharpe or
  mean OOS accuracy. Do not persist the single best-fold model; instead retrain on full
  data (with a final holdout) using the hyperparameters that produced the best mean
  cross-validated score.
```

```
  intervening `fit_iter()` will always receive the warming state ("RANGING") regardless
  of how much data is buffered. This silent degradation is easy to introduce.
SUGGESTED FIX: Document the required call sequence prominently in the class docstring
  and add a `push_and_fit()` convenience method that atomically pushes an observation
  and runs one EM iteration, reducing the chance of callers skipping `fit_iter()`:
  def push_and_fit(self, obs, em_iter=5):
      self.push_observation(obs)
      self.fit_iter(em_iterations=em_iter)
```

```
SEVERITY: LOW
TYPE: NumericalInstability
DESCRIPTION: `compute_psi()` skips any bin where `a < 1e-10 or e < 1e-10` with `continue`.
  This omits rare-category bins from the PSI sum, potentially underestimating drift in
  features with sparse tails. The standard PSI formula uses a small epsilon (1e-4) added
  to both numerator and denominator rather than dropping bins. Note: `health_monitor.py`

  are inconsistent.
SUGGESTED FIX: Use the standard epsilon-floor approach in both implementations:
  eps = 1e-4

      psi += (a - e) * math.log(a / e)
  Consolidate both PSI implementations into one shared utility.
```
